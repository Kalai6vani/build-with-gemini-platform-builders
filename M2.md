# Step 1 · See who can call the back office
M2 · Control the Connections — Instructions

M1 settled who each agent is and what data it may touch. M2 settles who may call whom.

# Key objective
Control who is allowed to call your most sensitive agent, by setting the list of permitted callers held on the agent itself in the Agent Platform.

- Read the list of who can reach the back-office agent that holds NovaSmart's cost and margin data.
- See what a lockdown would cost before you order one.
- Rewrite that list so it names one caller: the front-desk Price Match Agent.
- Watch the platform refuse the leftover test login, and watch a genuine price match above 10% still get its answer.
- Narrow what the back office itself can reach, and stop it changing the pricing data.
Why it matters: being allowed to read the margin data and being allowed to ask the agent that holds it are two different permissions. Until the second one is settled, anything in the project can pick up the phone.

# Where we left off
Every agent now signs in as itself, the shadow agent is catalogued and owned, and the marketing agent can no longer reach customer records. You can prove who did what. What you still cannot say is which agent is allowed to talk to which other agent.

Start where the risk is highest. Before you change anything, find out who can reach the agent holding your margin data today — not who is supposed to reach it, who can. Ask agy:

**Antigravity**
```text
Who can call our back-office margin agent right now?
```

What to expect: agy reads the back-office agent's own list of permitted callers and shows you what it says. There is exactly one name on it, a leftover service account called test-agent-caller, and the front desk is not on it at all. Nothing in your environment is changed.

---
# Step 2 · Check the cost, then lock it to the front desk
Same discipline you practised in M1: find out what a change would cost before you order it. You can ask for both in one sentence and the order still holds — agy shows you the impact first, and only then rewrites the back office's own list of permitted callers. Ask agy:

**Antigravity**
```text
Show me what would break if we locked the back office down to just the price-match agent, then make the change.
```

What to expect: first a plain-English readout of who can reach the back office today, which of those routes are real business traffic and which are not, and what would stop working if only the front desk were left, all of it in front of you before anything is changed. Then agy rewrites the list so the Price Match Agent is the only name on it, which closes the direct grant the rogue login was using, and shows you the list before and after; access changes take a minute or two to settle, so agy waits before it tests anything.

---
# Step 3 · Prove the rogue caller is out
Two things have to be true, and only testing both counts as a result: the rogue login is refused where it previously got through, and a genuine price match above 10% still escalates and comes back with a decision. Ask agy:

**Antigravity**
```text
Try calling it as that rogue login again, and check the real escalation still works.
```

What to expect: agy makes both calls for real. The call as test-agent-caller is refused where it previously succeeded, and agy quotes the platform's refusal back to you word for word. The genuine escalation goes through and a margin decision comes back from the back office.

---
# Step 4 · Lock down what the back office can reach and do
You have controlled who may call the back office. You have not controlled anything about what it does next, and it is the agent holding the confidential cost and margin data. Ask agy:

**Antigravity**
```text
Make sure the back office can only reach what it needs, and can only read the pricing data, not change it.
```

What to expect: agy puts the back-office agent behind the gateway NovaSmart already owns, which decides which destinations it may reach at all, and then narrows the agent's own database permissions so it can read the pricing tables but no longer write to them. Be prepared for a long pause; silence during it is normal, not a failure.

Verify that inbound access to the Markdown Strategy Agent is locked to the Price Match Agent, that rogue callers are blocked, and that egress filtering is enforced.

Ask agy:

**Antigravity**

```text
Verify our M2 connection controls and generate the Mission 2 Governance Scorecard.
```

What to expect: agy performs a live, read-only audit across connection controls (gateway attachment on Markdown Strategy Agent, test-agent-caller 403 refusal, Price Match Agent escalation verification, and outbound egress filtering), reports in one short line how many checks it evidenced, writes the full check-by-check table to a text file you can open, awards the Mission 2 achievement, and updates the cumulative governance scorecard HTML report (governance_scorecard.html).

# Step 6 · What's next
The back-office agent now names exactly one permitted caller, and the leftover login that used to reach it is refused. The one connection the business needs still works. Cloud permissions stack, though, so a handful of broad project-wide roles still carry the ability to call any agent in the project — real remaining work rather than a failure here, and the Reference Guide tab sets out where it sits.

All of that governs which agent may call which agent. It says nothing about what a person can type into a chat box, and a locked door does not help if you let a trap walk through it. M3 · Protect the Content is where you screen what customers can talk your agents into.

# See it in the console (Optional)
- Open the Agent Registry and find the Markdown Strategy Agent, the back office: https://console.cloud.google.com/agent-platform/agent-registry/agents
- Look at who may call it. The Price Match Agent should be the only name there, and test-agent-caller should be gone.
- That list is a setting on the agent itself rather than on the project, which is why this is the entry to look at.
- Open the Agent Gateway page and find novasmart-egress-gateway, the outbound gateway the back office now sits behind: https://console.cloud.google.com/agent-platform/gateways
- Both of NovaSmart's gateways were provisioned before this mission started, and neither had an agent attached to it. The Markdown Strategy Agent is the one this mission attached, and at this point it is the only agent behind a gateway.
- A gateway decides which destinations the agent behind it may reach on its way out. It does not decide who may call that agent, and it does not decide what that agent may do once its request arrives, which is why the caller list above and the narrowed database permissions are separate controls.

**Antigravity**
```text

```

This shows you which of the wider grants could be cut with no operational consequence and which ones the agents themselves depend on, so a clean-up ordered in good faith does not take the front desk down with it. Ask agy:

**Antigravity**
```text

```

This shows you the difference between closing an access list and retiring a credential, and where a working key for that leftover login is still sitting today. Ask agy:

**Antigravity**
```text
Does any other agent have a list like this, or is the back office the only one?
```

This shows you how far the pattern you just applied actually reaches, and what still decides who may call every other agent in the estate.
