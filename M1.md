# Step 1 · Register the shadow agent
M1 · Take Action — Instructions

M0 showed you the problem. M1 is where you fix it. You do it with two parts of the Agent Platform: Agent Registry, the catalog of what you run, and Agent Identity, the per-agent badge that makes every action traceable. In this lab agy moves at full speed: it acts directly rather than stopping to ask permission before each change, and everything it changes is recorded and can be undone.

# Key objective
Bring an uncatalogued agent under an owner in Agent Registry, and give every agent its own Agent Identity, so that each action traces back to one named agent.

- Register the promo agent, so it has a name and a named owner.
- Read what the shared login can do today, then give each agent its own login instead.
- Take customer-data access away from the agent that never needed it.
- Read the audit log back and see every read trace to exactly one agent.
Why it matters: while two agents share one login, nobody can say which of them read a customer record, and any access one of them needs, the other one gets.

# Where we left off
M0 turned up two problems, both on the marketing promo agent promo-agent-shadow:

- nobody had catalogued it, so no team owns it
- it shares one login with the Customer Personalization Agent, so their reads of the customer database cannot be told apart
Price Match and Markdown Strategy already sign in as themselves. Leadership's call is to own the promo agent, not kill it.

Something is running in your estate that no list knows about and no team owns. Put it on the official record, under a name you can hold accountable. Ask agy:

**Antigravity**
```text
Register the promo agent in our catalog, owned by the marketing team.
```

What to expect: agy finds the running promo agent, adds it to Agent Registry, the official catalog, with the marketing team as its named owner, and shows you the entry it created.

# Step 2 · Give each agent its own login, with only what it needs
Two agents still share one login, and separate identities on their own would only tell you who did what, not whether they should be doing it. So ask for the readout and the fix together: what that login can do today, one login each, and the access nobody needs taken away. Ask agy:

**Antigravity**
```text
Show me what that shared login can do, then give each agent its own login with only what its job needs.
```

What to expect: agy starts by reading out what the shared login can reach today, so you see the size of it before anything changes, then gives each workload its own identity and narrows what each one can reach. The two agents run on different infrastructure, so they get different kinds of identity and agy should say which is which; if the identity change has already closed marketing's route to customer data, agy tells you it is already closed rather than inventing a change, and either outcome is a pass.

Watch for the second half of that change: moving an agent onto its own login takes away the access it used to inherit from the shared one, so agy has to grant that access back before the agent can do its job again. Ask to see the agent actually retrieve customer data before you accept the step as done.

---
# Step 3 · Prove it worked
A fix you cannot evidence is not a fix. Go back to the same Cloud Audit Logs record of customer-data reads you pulled in M0 and see whether it can now answer the question it could not answer then. Ask agy:

**Antigravity**
```text
Show me the customer data log again. Can you prove who did what now?
```

What to expect: agy triggers a real read from each side, waits for the change to take effect, then reads the log back. Every read now traces to exactly one named agent — the personalization agent named in a different field of the log rather than the email column, which is blank for it now and should be — and the promo agent's attempt to read customer data appears as a denied entry.

# Questions worth asking
Each of these is a question a real leader would ask at this point. Ask agy:

**Antigravity**
```text
Show me everything you changed today. Did you touch anything I didn't ask for?
```

This makes agy list every change it made today, including the ones you never asked for, with the exact way to reverse each one. Ask agy:

**Antigravity**
```text
Is anyone else reading customer data, and did anything I did today change that?
```

This widens the log beyond the two agents in the story and shows you every identity that actually reads customer records. Ask agy:

**Antigravity**
```text
What would break if I just deleted that login?
```

This shows you what was depending on that shared login, which is the question worth asking before you take any access away rather than after.
